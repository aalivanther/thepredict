Changelog

What changed in ThePredict, newest first.

#Unreleased · release candidate rc1 (2026-10-12) and later local changes

No new version number or JAR yet: these changes sit on top of 0.0.1 and have not been verified on a live server.

#Fixed (2026-10-17)

  • PREDICTOR_PATTERN_<PATTERN> is now sent: once each time a pattern becomes active, to each mob of the encounter whose target is that enemy and that has a handler, and only in the bias and full pattern modes. See Patterns.
  • A pattern's rest now ends after patterns.restTicks: the pattern comes back active if the habit still holds, which counts as a new activation and sends its signal again, or turns inactive otherwise. Before, a rested pattern stayed resting. The pattern statistics now count as activations only the moments a pattern becomes active.
  • Group.Questions now decides which questions go to Jev in full: plan_and_leader and leader_only ask only the leader, plan_only sends only the group plan question, and members is unchanged. The other members keep playing locally. For five members, a plan_and_leader request went from about 22 400 to about 7 000 characters. See Groups.
  • The search_last_known plan is offered when no member sees its target and one saw it at most group.lkpForgetTicks ago. Plan candidates are one per family, with the local plan first.
  • An overlay's Timing.TickLayer above decision.tickLayer.mode is lowered to the global mode with a warning, like a profile's.
  • The ANSWER_* primitive of an Intention line sets the answer of the skill's tell when the choice declares no Telegraph.Answer.
  • patterns.maxExploitShare, patterns.maxReadsPerTick, patterns.maxFactsPerRequest, group.maxSquads, group.lkpForgetTicks and the profile key Group.Roles now take effect.
  • Stances.Native, Difficulty.NativeLevel, Decision.Pruning and Decision.Diversity accept a bare off or on.
  • eval verdict import <file> reads only inside the plugin folder and refuses any other path with path: must stay inside the plugin folder.
  • Keys this build accepts but does not read log has no effect in this build at load when they hold a value other than the shipped one. None was removed.
  • Without a session, <caster.predictor.level> and <caster.predictor.confidence> show none, like the other placeholders (before: base and 0.00).
  • No shipped default changed.

#Added

  • Configuration in the MythicMobs folder. config.yml and the profiles now live in plugins/MythicMobs/AIConfig/ (config.yml and Profiles/). The first start creates the folder only when it is missing and never overwrites a file. Generated data stays in plugins/ThePredict/. See Install & requirements.
  • The Intention line. Each MythicMobs skill says what it is for in one line (Intention: DAMAGE, MELEE, DAMAGE_MEDIUM, WHEN_TARGET_IN_MELEE). Vocabulary v2 has 43 primitives, including five ANSWER_* primitives for tells. Reach, radius, wind-up, cooldown and charges are still read from the native skill, not from the line. See Skills & intents.
  • Skills fire on their own cooldown. With the new default decision.castMode: any_ready, every skill with a valid Intention line fires on the first tick it is ready, at the pace of its native Cooldown and Charges. intent_only keeps the 0.0.1 behavior (only the tactic's skill). Profiles choose with Timing.CastMode.
  • /thepredict intention suggest [profile] prints the canonical Intention line of every bound choice. It never writes MythicMobs files.
  • Per-tick layer. Between two decisions the mob reacts within ticks (evade at critical health, punish a drinking target, respect a raised shield, finish a low target) and, with full, runs short micro-movements. New: decision.tickLayer.*, the reactive cadence per profile (standard is the saving mode), debug.seed and /thepredict inspect <mob> tick. See How a fight runs.
  • Records and aggregates. Append-only JSONL records in plugins/ThePredict/records/ (14 days, 2 GB by default) and a SQLite aggregates.db beside them, through the driver Paper already ships. New: records.*, storage.*, /thepredict records and thepredict.records. See Storage & records.
  • Difficulty by target fight length and Entropy. Presets Fácil, Normal, Difícil, Caos and Vacío per mob (PredictorDifficulty), the opt-in lethal mode PredictorEntropy, per-world overrides, the <caster.predictor.pressure> placeholder and /thepredict eval with thepredict.eval. See Difficulty.
  • Stances, tells and poise. Stances, Telegraph and Poise profile sections, global telegraph.* and stance.* keys, feints, the predictorstance condition and the stance, poise, answer and telegraph placeholders. ThePredict adds no effects: tells are PREDICTOR_TELL_* and PREDICTOR_STANCE_* signals for your own skills. See Stances, tells & poise.
  • Terrain zone. Real-time reading of the ground around a fight: zone.*, the Zone profile section, the predictorzone condition, the zone and pushdanger placeholders and /thepredict zone. An edge is a drop bigger than zone.maxSafeDropBlocks (3). See Zones & terrain.
  • Group coordination. Attack tokens and impact spacing per player, roles, squads, leaders and group plans: group.*, the Group profile section, the predictorrole, predictorplan and predictortoken conditions, five placeholders and /thepredict inspect <mob> group. See Groups.
  • Enemy patterns. Habits of each enemy read from its movement: patterns.* (default observe, which never changes a decision), the Patterns profile section, the predictorpattern condition and the pattern and forecast placeholders. See Patterns.
  • Learning data. learning.collect (on by default) records outcome windows without changing any decision or request; PredictorTraining lets a mob explore against players; calibration options and /thepredict learn with thepredict.learn. See Learning & training.
  • Profile overlays. /thepredict autoconfig with thepredict.autoconfig applies an administrator's key-value overlay to one profile without touching the author's file. Nothing is applied automatically. See Profile overlays.

#Changed

  • A skill without a valid Intention line (and without an administrator Purpose) is untyped: it fires only as the choice of its own tactic. PredictValues no longer produce a purpose; they are kept as history.
  • Purpose in a profile choice stays as an administrator override and wins over the skill's line.
  • ThePredict no longer reads raw player input: a player's tendency comes from observed movement.
  • decision.tickLayer.mode: off is an error; use casts.
  • The shipped config.yml no longer has the obsolete decision.maxReadyChecksPerTick. An older file that still has it starts with an INFO line and nothing changes.
  • /thepredict learn status shows collect and scope from the loaded config.yml.
  • The ThePredict-Zone thread starts with the first zone build and stops after a second without work.
  • Pattern summaries are written to the records.
  • Performance improvements in hot paths.

#Migration notes

  • If the old location (plugins/ThePredict/config.yml or plugins/ThePredict/AI/) has content and AIConfig/ has none, ThePredict loads nothing, enables no request and writes a proposal under plugins/ThePredict/migration/. Copy the .proposed files into plugins/MythicMobs/AIConfig/ by hand. If both locations have content, AIConfig/ wins and the old files are ignored. Nothing is ever moved or deleted.
  • To move a profile from Purpose to Intention: run /thepredict intention suggest <profile>, copy each line into its skill, /mm reload, check that inspect shows origin=skill, then remove Purpose.

Note Coming next

The difficulty presets, Entropy, tells, the push policy toward players and the group fairness rules listed above will be redefined in an upcoming release, which replaces target-time difficulty with intelligence levels. The pages that describe them carry a changing soon mark.

#0.0.1 · 2026-09-29 · candidate

The first candidate: built and covered by automated tests, with the Jev client checked against the real TypeSafe account. Hosted acceptance on a Paper server is still pending.

#Added

  • Direct Jev client (TypeSafe System One): a free service check (GET /v1/models) and one request per encounter with contingencies, an English combat summary with player aliases, and a size guard.
  • Movement ownership. Movement goals generated from the profile and installed through the MythicMobs AI API, plus the Paper goals thepredict:hold, thepredict:flank and thepredict:owner.
  • Sessions and encounters per mob, a per-tick coordinator with request, token and work budgets, and growing pauses when the service fails.
  • Tactical execution with the four-level fallback chain (JEV, ALTERNATIVE, LOCAL, BASE), a re-check of reach and conditions before every skill, invulnerability frames, shields and flanking.
  • MythicMobs vocabulary: predictorcontrol, predictormove, predictortactic, the predictordecide mechanic, <caster.predictor.*> placeholders and PREDICTOR_<TACTIC> signals.
  • Enriched threat on top of the MythicMobs threat table: assists, blocked hits, ranged harassment and unreachable targets.
  • Commands status, check, inspect and debug intent|release|goals, with thepredict.admin and thepredict.debug (off by default).
  • Example boss ThePredictGuardian and a profile template, created on the first start without replacing anything.
  • Skill purposes: what each skill is for, its reach and its risks, the cooldown class read from the native Cooldown, and a warning for tactics whose movement can never cast their skill.
  • Better questions to Jev: identical tactics are merged (with a warning), at most 8 options per question with the current tactic always kept, three detail levels (compact, standard, full), optional fit checks, and outcome windows in status and inspect.
  • Entities as participants: the participants section and the profile's Participants with native selectors (type:, tag:, category:, kind:, mythic:, faction:, team:, tagged:, predictor). Sides follow MythicMobs factions and scoreboard teams. Jev only receives entity_N aliases and the species. Defaults stay players only.
  • Duel recorder /thepredict duel start|status|stop (needs thepredict.debug, off by default).
  • Optional scenario recording (debug.recordScenarios).

#Changed

  • config.yml and profiles use the strict schema 2: an unknown key is an error with the file and path.
  • Defaults: decision.questionDetail: full and decision.minimumConfidence: 0.45, chosen from a labelled benchmark.
  • A tactic's skill fires on its own Cooldown: every 2 ticks ThePredict checks whether it is ready again. Tune each skill's Cooldown to control spam. A vanilla hit keeps the vanilla rhythm of one hit every 20 ticks.
  • The example skills and template use healthpercent{p=<30%}: health{h=…} compares absolute health and fails with % in MythicMobs 5.13.1. If you copied the example before, change those lines.
  • Requests are prepared on the server thread before any budget is reserved; a request with nothing left to ask is not sent. A request that cannot be prepared only affects its own encounter and never pauses the service.
  • The budget reserves tokens by the real size of each prepared request.

#Removed

  • The old provider based on OpenRouter and its provider section. The migrator only recognizes it to propose a migration; an old key is never copied.

#Migration from schema 1

There is no migration command, and ThePredict never changes your files. When it finds schema 1 files it loads nothing from them and writes a proposal (config.yml.proposed, the proposed profiles and report.md). Limits with an equivalent are carried over (for example decision.maxConcurrentRequests becomes decision.maxInFlightRequests), each choice becomes a tactic without movement, each Operation becomes the matching shortcut context and DirectChoice becomes DirectTactic. Apply it by hand, set TYPESAFE_API_KEY, start, run /thepredict status, and then add movements to the converted tactics.

#Known limits

  • In-game behavior and host capacity are pending verification on a live server.
  • Ground mobs only; species with a Brain only accept Movement: NONE; skills already started (delays, projectiles) are not cancelled.
  • A stuck local mob repeats its PREDICTOR_<TACTIC> signal.
  • Context conditions that need skill data (trigger, skill target, metadata) are always false.
  • While ThePredict controls a mob, its base melee goal does not hit: put melee damage in a skill.
  • Folia is not supported.
