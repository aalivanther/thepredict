Getting started

Install & requirements

What ThePredict needs, what the first start creates, where every file lives and how to move an older configuration.

#Requirements

ComponentVersionNotes
Java25 or newerChecked at startup.
Paper26.2Folia is not supported.
MythicMobs Premium5.13.1 or newerRequired dependency (depend: [MythicMobs]).
A TypeSafe key—Optional. Only needed for Jev to decide; without it mobs fight with their profile's local planner, at no cost. See Jev connection.

The combination tested while building this release is Java 25, Paper 26.2 (build 129), MythicMobs Premium 5.13.1 and the Jev model jev-1.13.0. Any other combination is untested.

A wrong version disables the plugin at startup with one of these lines:

Console
Startup prerequisite failed: Java <n> is unsupported; ThePredict requires Java 25 or newer
Startup prerequisite failed: Minecraft <version> is unsupported; this Paper build requires 26.2 or newer
Startup prerequisite failed: MythicMobs <version> is unsupported; minimum version is 5.13.1

#Install

  1. Put the ThePredict JAR (for example ThePredict-{{fact:plugin.version}}.jar) in plugins/, next to MythicMobs Premium.
  2. Start the server. The first start creates only the files that are missing and never replaces one that exists:
    • plugins/MythicMobs/AIConfig/config.yml: the master file (schema 2, empty key, tested model).
    • plugins/MythicMobs/AIConfig/Profiles/README.txt and Profiles/example.yml.example: a profile template, ignored until you copy it to a .yml file.
    • plugins/ThePredict/examples/: the example boss (a mob, its skills and its profile), inactive where it is. examples/README.txt explains how to try it.
  3. Read the console. A fresh install is not an error; each line says what to do next:
Console
Jev not configured: set TYPESAFE_API_KEY or jev.apiKey. MythicMobs works normally. Next: set the key and restart the server, then run /thepredict status.
No profiles: copy examples/ or create a .yml file in plugins/MythicMobs/AIConfig/Profiles/. Next: read plugins/MythicMobs/AIConfig/Profiles/README.txt.

With profiles but no mob set to Predictor: true yet, it says <n> profiles read, but no mob targeted by a profile has Predictor: true. Next: set Predictor: true on the MythicMobs mob and run /mm reload.

  1. Optional: set the Jev key and restart (see Jev connection). With a key, ThePredict checks the service without spending tokens and reports, for example: Jev check: READY (credential valid; model unverified until first inference). Decisions are enabled.
  2. Continue with the Quick start.

An administrator with thepredict.admin who joins gets one line when something needs attention, for example [ThePredict] some profiles have errors; Jev is UNCONFIGURED. Run /thepredict status for details.

#Where things live

People edit files in the MythicMobs data folder; ThePredict keeps everything it generates in its own folder. Outside AIConfig/, ThePredict writes nothing inside plugins/MythicMobs/.

WhatWhere
Master configurationplugins/MythicMobs/AIConfig/config.yml
Profiles (.yml and .yaml)plugins/MythicMobs/AIConfig/Profiles/
Profile templateProfiles/README.txt and Profiles/example.yml.example (not loaded)
Example bossplugins/ThePredict/examples/
Records, backups, exportsplugins/ThePredict/records/ (with backups/, exports/ and a .lock)
Aggregates databaseplugins/ThePredict/aggregates.db, beside records/, not inside
Duels, scenarios, migration proposalsplugins/ThePredict/duels/, scenarios/, migration/
Learning and overlaysplugins/ThePredict/learn/, plugins/ThePredict/autoconfig/

#Reloads and restarts

You changedDo this
config.yml or the keyRestart the server. Both are read only at startup. /thepredict check re-checks the service with the key already loaded; it does not read a new one.
A profile/mm reload. It re-reads MythicMobs mobs and skills, then re-reads and re-binds every profile.
A mob or a skill/mm reload.
A datapack tag used in a selector/minecraft:reload, then /mm reload.

There is no /thepredict reload.

Watch out A broken config.yml keeps ThePredict off

An unknown key, a key from the old schema or a value out of range keeps ThePredict inactive, and the console names the problem: Invalid configuration: AIConfig/config.yml: <path>: <reason>. ThePredict stays inactive and /thepredict status still works. MythicMobs keeps working, and storage is not opened (no records/, no aggregates.db). Fix the file and restart.

#Moving from the old location

Older builds kept their files in plugins/ThePredict/config.yml and plugins/ThePredict/AI/. ThePredict never moves or deletes them; what happens depends on where your files are:

  • Only the old location has content (the master file, or a .yml in AI/): ThePredict loads nothing from it, enables no requests and writes a proposal in plugins/ThePredict/migration/<yyyyMMdd-HHmmss>/ with AIConfig/config.yml.proposed, one AIConfig/Profiles/<file>.proposed per profile and a report.md. The console says Migration proposal: review <report> and the .proposed files next to it, then copy them into plugins/MythicMobs/AIConfig/ by hand. No file was changed and no query was enabled. The same proposal is reused on every start while your files do not change.
  • Both locations have content: AIConfig/ wins. The console, /thepredict status and the join notice say Old files in plugins/ThePredict/config.yml and plugins/ThePredict/AI/ are ignored because plugins/MythicMobs/AIConfig/ already has configuration. Nothing was moved or deleted.
  • Only the new location has content: no notice.

README.txt and example.yml.example do not count as content.

#Migrating from schema 1

There is no migration command: ThePredict never changes your files. When it finds schema 1 files (a master file with a provider section or other old keys, or profiles with Behaviors, Operations or no Tactics), it does not load them and writes the same kind of proposal as above, already converted to schema 2 and to the new paths.

How to apply a proposal:

  1. Stop the server and keep a copy of plugins/MythicMobs/AIConfig/ and of any old plugins/ThePredict/config.yml and AI/ files.
  2. Read every decision in report.md and fix what it lists under manual review.
  3. Copy each .proposed file into plugins/MythicMobs/ and remove the .proposed extension (AIConfig/config.yml.proposed becomes plugins/MythicMobs/AIConfig/config.yml).
  4. Set TYPESAFE_API_KEY yourself. A key from the old provider is never copied, because it is not a TypeSafe key.
  5. Start the server and run /thepredict status. Keep the old files until status no longer asks for the proposal.

What the converter does: the provider section becomes jev with the tested model and an empty key; limits with an equivalent move over when they fit the new ranges (for example decision.maxConcurrentRequests becomes decision.maxInFlightRequests, profileDefaults.decisionIntervalTicks becomes minimumDecisionIntervalTicks, profileDefaults.lowHealthRatio becomes criticalHealthRatio); keys without an equivalent are listed with the reason; each old choice becomes a tactic without movement; each Operation becomes the matching shortcut context; DirectChoice becomes DirectTactic. After migrating, give your tactics a movement (see Movement & goals).

#Turning it off

  • One mob: set Predictor: false in its MythicMobs file and run /mm reload. ThePredict closes the session, removes its goals and MythicMobs puts the mob's own AIGoalSelectors back. Removing the mob's profile from Profiles/ and running /mm reload does the same.
  • The whole plugin: remove the JAR and restart. On shutdown ThePredict stops its task, cancels requests in flight, sets every predictor* condition to false, releases the goals of its sessions, stops a duel recording, flushes records and aggregates, and closes the Jev client last. It can take a couple of seconds longer while scenario recording or the records writer is flushing.
  • No key: nothing leaves the server, and bound mobs fight with their profile's local planner.
